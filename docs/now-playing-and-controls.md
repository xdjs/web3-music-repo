# Now Playing and recording controls

Recording buttons use one state model and the existing Music Nerd SVG icons. Cards, song pages, historical playlist rows, personal/shared playlist rows, wallet cards, and queue entries synchronize with the same media element. The playing recording offers Pause; paused, failed, or ended media offers Play. A pending metadata request can be paused before it resolves. Resuming the current recording leaves its source, time, and queue intact. Distinct duplicate occurrences in the listening queue remain separate Play actions.

Starting or resuming a recording stays on the browsing page on desktop and mobile. The compact player has separate song and artist links, an explicit desktop expand button, and a mobile artwork expand affordance. Expanded song and artist links close Now Playing and navigate without stopping playback. Back and Escape close it without routing or replacing the page underneath, restoring its scroll and focus. Next and automatic advance update the open dialog, but do not reopen a dialog the listener closed. The queue can open above Now Playing and closes independently.

The dialog reuses the existing typography, surfaces, accent, icons, seek control, and transport behavior. It has artwork or video, title/artist, pause/play, previous/next, shuffle, likes, and queue. Desktop retains volume/mute; mobile and coarse-pointer layouts omit both and retain seek. Source information is available on the song details/provenance page, outside the playback chrome. One audio element continues playback throughout. The single native media element stays permanently mounted beneath the compact artwork, outside the closed overlay. Opening Now Playing positions that same element over its media slot, preserving the source and decoder without cloning or reparenting. The native dialog uses nonmodal display with background inertness, manual keyboard wrapping and Escape, so its media sibling can remain rendered. A native modal queue can still appear above both. Video uses object-fit contain; audio recordings display cover art. No second player or runtime reparenting is introduced. Real Planet X video remained playing across Back with the same source and exactly one media element (`data/now-playing-video-verification.json`).

The Explore subtitle is “Find songs, artists, and collections from the web3 music era”. Artist pages initially render 40 recordings and retain their expanded limit when returning. Details promotes the preserved metadata description, retaining line breaks, and omits editorial `record.note` copy and the duplicate collapsed description. Existing BPM/key badges remain above the original description. Preserved Spinamp audio explains whether the original reference was missing or retained on an unsupported storage host.

## Planet X overlap report and browser media controls

The user reported hearing delayed overlapping copies around 1:50–2:00 in production; pausing stopped all sound. The user subsequently confirmed hearing the same doubling in the original IPFS media; replacement master media is pending. The app does not claim to repair that source. `scripts/verify-playback-overlap.mjs` inspected production with instrumentation covering both DOM and dynamically created/detached media elements. After seeking to 1:48 and playing through 2:00, there was exactly one active media element and one `play()` call, using the original Planet X IPFS video. Pause stopped it. The next-track buffer does not warm while the current work is a video. This bounded check does not establish what the user heard or exclude an effect in the media source; it is not a complete reproduction from the beginning of the song.

Chrome's wrong song title was separately explained by missing MediaSession metadata: its fallback used the underlying page title. The new frontend explicitly sets the active recording's title, artist, artwork, and playback state, and registers native media-control actions. Local verification shows Planet X / Xmane & Pete Rango remains in MediaSession after navigating to NOT4ME. Receipt: `data/playback-overlap-investigation.json`. This fix is on the working branch, not proof of a production fix for the audible overlap.

## Mobile controls and video detection follow-up

The close control is a shared down-chevron with the accessible name “Back to discovery”. Pointer/touch opening and closing preserve focus without displaying a keyboard-only focus ring. Keyboard input restores the standard visible ring; Tab wrapping, Escape and original focus return remain intact.

Now Playing no longer renders storage/source text or a provenance link below the controls. The bottom player is also empty at rest below the artist; only transient loading, retry, or unavailable messages remain in its live status region. Mobile/coarse-pointer layouts hide both volume and mute while retaining the seek control and centering Play/Pause.

Some Spinamp imports labeled as audio are actually videos. The single native media element now detects positive video dimensions on metadata/data/resize/playing events, shows the video in the artwork slot, and disables competing next-track buffering while video is active. Before detection it remains laid out beneath the artwork instead of `display:none`, avoiding hidden-video startup on WebKit. This changes presentation based on decoded media; it does not overwrite catalog provenance or create another player.

`data/now-playing-mobile-verification.json` passes desktop Chromium and touch WebKit checks, with inspected 1440/390/320px light/dark captures. `data/runtime-video-verification.json` proves actual Helmet City video (1536×896) and Base Day Two video (1920×1080) began playing inside Now Playing before Back, using their original media URLs. Both continued after Back with one element and the same source. These checks use WebKit mobile emulation, not a physical iPhone; a final device check after deployment remains useful.

## In-context playback, responsive layout, and seek release

`data/context-player-verification.json` verifies actual Mija audio on desktop Chromium and touch WebKit: normal Play stays in context, compact/expanded song and artist links navigate correctly, and explicit expand/Back preserves the source and advancing playback. Fourteen rendered layouts cover 1440px desktop and short/tall 320/390/430px mobile in both themes. Media fits the remaining viewport while controls retain 32px bottom space on mobile, without overflow or stretched artwork.

Both seek sliders now preview native thumb movement without seeking the decoder on each intermediate input. Native change commits one position, and playback time updates cannot overwrite an active drag. `tests/seek-range.test.mjs` covers cancellation, keyboard and bounded values. `data/seek-release-verification.json` verifies actual Base Day Two video with Chromium mouse and native CDP touch: no seeks while dragging, exactly one at release (~26.7 seconds), then keyboard rewind. This is not physical-iPhone proof, and it does not alter the original Planet X audio. Reproducers: `scripts/verify-context-player.mjs` and `scripts/verify-seek-release.mjs`.

`data/context-player-video-verification.json` confirms actual Base Day Two video starts while collapsed in touch WebKit (1920×1080), expands into the aligned media window, and continues through Back/reopening with one element and unchanged source. It also checks focus wrapping, background inertness, and queue stacking/Escape. A separate Helmet City attempt timed out before playback after 40 seconds; this source/network result remains unverified for this checkpoint, and the change is not a claim of universal startup success.
