# Conservative native-player warming

`createMediaPreloader` in `src/media-preload.mjs` prepares one audio candidate in the same HTML media element used for playback. Schedule only an already resolved first-visible track (or explicit pointer/focus intent); do not resolve the entire catalog. The helper waits 650ms, allows at most two starts per minute, and rejects video, hidden/offline pages, Save-Data, 2G/3G connections, and occupied players. `isBusy` must include both active/current playback and pending user play intent. Call `cancel()` when a route/filter makes the candidate irrelevant.

The native player requests metadata with a two-second deadline. If metadata does not arrive, the request is canceled by clearing the source; this intentionally loses any incomplete warm buffer. If metadata arrives, `preload` becomes `none` and the source remains attached. On play, call `take(id, exactURL)` before assigning the source. A true result means keep the existing source and call play without assigning src or invoking load again. A different URL/record falls back normally.

Browser preload is a hint, not a strict byte budget. The limits are one native element/candidate, rate, duration and connection policy; the browser controls actual byte requests and may fetch beyond the metadata. No whole-catalog or explicit whole-file download is issued, and there is no claim of a hard memory or transferred-byte cap. A hard reusable byte budget would require a separate streaming cache or MediaSource integration.

Six unit tests cover source preservation, incomplete-request cancellation, safety/connection policy, rate/concurrency limits, visibility changes, and active-playback protection. `scripts/verify-media-preload.mjs` passed with the real Mija CDN media: one load/loadstart before and after adoption, no additional emptied event, and advancing playback. Chromium fetched the MP4 beginning and tail for metadata, then continued at byte 32768 on playback. A cold NOT4ME attempt exceeded the deadline and was canceled; that outcome is preserved separately in `data/media-preload-cold-timeout.json`. These results prove native reuse when warming succeeds, not universal latency improvement. Integrated app and final deployment verification are separate checks.
