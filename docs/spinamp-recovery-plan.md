# Spinamp as an additional recovery source

Checked 2026-11-06. Spinamp is the best newly discovered bootstrap index for this recovery: the live public API exposes exact NFT relationships as well as processed music, and the upstream indexer source explains its methods. This does not establish that every indexed item remains playable, that each entry is a distinct composition, or that any platform is completely represented.

## What we retrieved

The read-only public endpoint is https://api.spinamp.xyz/v3/graphql. `scripts/spinamp-inventory.mjs` exhausted 106 cursor pages and recovered **52,987 unique processed-track IDs**. All pages reported the same total. `data/spinamp/inventory.json.gz` stores selected public track/artist-name/media fields, not private profiles; `inventory-manifest.json` records queries, timestamps, page counts, hashes and completion. Raw responses remain ignored in `work/spinamp/`.

There are 54 populated platform IDs (55 registered). Largest cohorts: Sound 18,247; OMGKirby 8,546; Nina 6,206; Zora 5,802; Song-a-day 5,449; Catalog 2,468; Pods 2,308; Lens 697; Supercollector 579; NOIZD 508; InvestInMusic 456; Spinamp 372. Generative editions, podcasts and other audio are present: these counts are not automatically equivalent to a curated song discography.

ID prefixes span Ethereum 20,626; Base 11,549; Optimism 9,184; Solana 6,215; Zora 4,092; Polygon 856; NOIZD 464; Sepolia 1. These prefixes are discovery hints; exact chain/contract/token identities come from the NFT relationship table.

The baseline comparison was our **9,209** records. Initial identity/media audit found 3,514 exact selected-token matches, 7,665 same-contract matches and 4,954 matching media references. These overlap. 45,301 entries had neither a parsed same-contract nor media match, **not 45,301 proven missing songs**. Nonstandard processed IDs undercount parsed contract overlap. Catalog had 2,467 exact selected-token matches and all 2,468 shared contracts; MintSongs had 138 exact selected-token matches and all 139 matching media references. Sound and Zora offer the most useful near-term gaps. See `coverage-audit.json` and compressed `identity-matches.json.gz`.

## How Spinamp sources the data

Official sources:

- [Spindexer](https://github.com/spinamp/spindexer), inspected commit `dfb0108b694c6dd826934283a08fd93892ab6983` dated **2022-12-08**, AGPL-3.0. This public snapshot is older than the current API; it cannot alone document the live Base/Zora-chain deployments.
- [SDK](https://github.com/spinamp/spinamp-sdk), inspected commit `a4a1da7c679fd28fc91f1f8871767024ed8be686`, MIT. SDK query definitions document the public track, artist, NFT and playlist relationships.
- [Architecture](https://github.com/spinamp/spindexer/blob/dfb0108b694c6dd826934283a08fd93892ab6983/Architecture.md): resumable processors track blocks/cursors and metadata stages independently, with failures isolated rather than turning failed reads into empty success.

The code combines direct onchain event/contract reads with platform APIs and decentralized metadata. Sound's `soundArtistProfileCreator.ts` listens for `CreatedArtist`; `soundCreatorV1.ts` listens for `SoundEditionCreated`, captures deployment starting blocks and distinguishes official Sound from Sound Protocol using Sound API enrichment. The older Sound mapper reads NFT `animation_url`, title/artist/profile context from `api.sound.xyz/graphql`, and uses edition-aware track grouping. Catalog similarly enriches NFT identity with Catalog API artist and track data; its lossy audio may use Catalog's CDN. Zora's `zoraDropCreator.ts` listens for `CreatedDrop`, captures creator and contract, and discovers editions. Nina's `triggers/nina.ts` reads release accounts from a Solana Anchor program and Metaplex mint metadata. Original Zora uses its distinct token metadata getter. Dynamic platform field extractors map different metadata schemas into tracks.

**Recommendation:** bootstrap exact identities and preserved metadata from the running public index now; independently verify original tokenURI/uri and media in bounded background passes. Use the upstream adapter/event structure to expand our own gap scans and provenance. Rebuilding the whole historical index first would repeat work and depend on old centralized APIs. Hosting Spindexer could later provide an independent index, but the public code is old and its dependencies/AGPL obligations need separate evaluation. We copied no upstream implementation into our application.

## Exact NFT import, not guessed token IDs

Processed IDs often end in a hash or song slug. Those are **not token IDs**. A nested `allProcessedTracks → nftsProcessedTracks...` query timed out even at 25 records. Efficient alternative: batch aliases of `allNftsProcessedTracks(condition:{processedTrackId: ...},first:1)` and select the exact NFT's `chainId`, `contractAddress`, `tokenId`, `tokenUri`, `mimeType` and factory `standard`. Public schema introspection showed no `distinctOn` argument. `scripts/spinamp-resolve-nfts.mjs` initially ran 50 aliases sequentially and now uses 25 to reduce per-field timeouts, pauses between requests, uses a timeout and bounded batch count, and checkpoints compact public references. Per-field errors remain retryable; an empty successful relation is distinct from a provider failure.

`scripts/spinamp-import.mjs` builds `data/spinamp/recovered-media.json` with normal records/evidence/proposedPeople. It admits only explicitly linked ERC721/ERC1155 NFTs on currently supported Ethereum, Optimism, Base, Polygon and Zora chains. It requires media distinct from artwork and indexed audio evidence, preserves source identity/platform labels, excludes attribution conflicts, and deduplicates exact NFTs and same-contract/same-content editions. Original NFT metadata media is preferred. If that field is empty, an exact NFT-linked track may use separately retained Spinamp audio, explicitly labeled as preserved/indexed media. It never coerces Solana, unknown chains, hash suffixes or missing IDs into Ethereum/token zero. Token zero is valid only when explicitly supplied by the NFT relation. Artist IDs are stable vendor IDs, avoiding name-only collisions; root must preserve them in mergeCatalog.

Evidence is `status: indexed`, `onchainVerified: false`, `playbackVerified: false`. These imports do not inherit the verification status of our older independently recovered records. Spinamp's `lossyAudioIpfsHash` can represent transcoded audio: it is retained in the inventory and any fallback is explicitly marked `sourceType: spinamp-processed-media`, `mediaSourceType: spinamp-preserved-audio`, `originalMediaMissing: true`. The player must say Spinamp preserved audio, not original onchain media. No prices, collector balances or ownership values are labeled artist revenue. Import summary and compressed exclusion/duplicate audit are regenerated at each checkpoint; do not assume reference resolution is complete until its explicit completion flag is true.

One concrete cross-check: Cherele's HOOTY HOO on Base maps to contract `0x65B62eFd85e8Ec56E44A682861d4639947Cf5FD6`, token `1`, indexed creation block `18465131`, an Arweave metadata URI, BPM 160 and C major. Its NFT metadata audio fields are empty, while the processed track retains a playable candidate audio URL. This is additional indexer evidence; it is not a fresh independent chain verification. A separate attribution conflict was caught: Spinamp's Pete Rango artist association for ROUND N ROUND conflicts with its NFT metadata artist LIL LIL, so that row is held for review.

## Public playlists and useful interactions

The current public playlist API at `https://us-central1-spinamp-prod-re.cloudfunctions.net/playlist?verified=true` returned seven featured public playlists with 72 ordered entries. `public-playlists.json` retains playlist title, public curator wallet, ordered track IDs, source update date and verification/permanence flags. These are **Spinamp playlists, not historical Sound playlists**, and are offchain curation. The SDK's older default endpoint differs from the live app host.

The actual desktop home was rendered and inspected (`captures/spinamp-home.png`). Useful concepts: genre browsing; trending and latest discovery; cross-platform artist pages; visible queue/player; distinct library, favorites, playlists and history; and a random-track action. Preserve our established Music Nerd/Sound visual language rather than copying Spinamp's cream/shadow-card style. Deeper queue actions and mobile interaction have not been independently reviewed in this pass.

## Integration boundaries

The current frontend receives roughly 30MB decoded for 9,209 entries. A 53k expansion needs server-side pagination/search plus lazy record detail and profile loading before indiscriminate full-catalog delivery. Parent owns that work and shared loader integration. Keep compressed inventory/research artifacts out of function bundles where unnecessary. Use the generated import summary for actual eligible counts/bytes, not the full inventory count. Solana/Nina requires a separate chain adapter. Unknown standards, absent NFT relations, image-only records and creator conflicts remain visible recovery leads, not fabricated playable entries.
