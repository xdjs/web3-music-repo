# Supercollector public catalog recovery

Yes: the current public Supercollector catalog is enumerable. The official [release search endpoint](https://release.supercollector.xyz/api/releases/search), called without a search term, returned **152 releases containing 717 track entries**. The official [artist directory](https://release.supercollector.xyz/artists) listed **74 artists**, with exactly the same 152 distinct release IDs. All 152 corresponding public release pages were read successfully, with 717 track entries reconciled by exact release UUID, track UUID and number. This is a complete snapshot of those two current visible listings, not proof of every historical, deleted, private or unlisted release.

All 152 pages explicitly identify **Optimism (chain 10)**. Releases have a contract address; tracks have individual token numbers and metadata references. They are not collapsed into one album NFT. The sample [LIL LIL / Pete Rango contract](https://optimistic.etherscan.io/address/0x0b0AbF42c6cD9Eb5803E39988850df4756A07956) resolves to a verified DCNTSeries implementation with ERC-1155 functions/events; its relevant ABI and implementation source link are preserved in `data/supercollector/contract-reference.json`. A separate fixed-block RPC audit checks ERC-1155 support on all release contracts and reads public track URIs. Do not describe indexed data as a full all-time factory census.

The importer deliberately checks the release page's access state rather than treating every URL exposed by a search result as permission to play. **623 tracks are explicitly released, `gatekeep:false`, `gatekeep_mode:allow_all`. Another 94 are marked unreleased without a false gatekeep flag**; their audio and per-track metadata links are withheld from exported snapshots and they are not imported into playback. Of the 623 public tracks, seven lack usable per-track metadata URI references in the index and are retained as unresolved identities rather than guessed. The initial playback bundle therefore contains **616 records**, each with a distinct chain/contract/token identity and a public audio reference. No same-contract duplicate media URI was found among these 616.

`data/supercollector/inventory.json` retains all 152 release/717 track identities and access classifications. `data/supercollector/recovered-media.json` contains the 616 additive playback records, their metadata, provenance and 101 withheld/unresolved entries. Private account fields from page payloads are excluded through explicit field allowlists; raw public page payloads are not committed. Artist links are retained only when explicitly public HTTPS links. Release and track IDs, release title and track number remain available for album association.

Musical metadata is unusually useful here: the initial 616-record bundle has **58 tracks with original BPM, 47 with original key, and 283 with credits**. The official [LIL LIL release](https://release.supercollector.xyz/lil-lil-lil-lil-pete-rango) includes OFF THE LEASH (150 BPM, Dmin), ROUND N ROUND (150 BPM, Bbmin), and BLACK PETAL ROSES FT OYABUN (125 BPM, Gmin), with explicit Peter Arango writing/production credits. These are source-supplied fields, not audio estimates.

Three public-source Chromium start checks passed: OFF THE LEASH, Misplaced, and Thin Mints. The report is `data/supercollector/playback-verification.json`. These checks establish actual audio start for those three URLs only, not full-track auditions, verification of every media object, or integration into the production archive UI.

Reproduce with `node scripts/import-supercollector.mjs` (refreshes public-page access checks; use `--resume` only to continue a recent interrupted snapshot; no writes to the source service) and `node scripts/verify-supercollector-chain.mjs` (resumable fixed-block read-only RPC audit). Provider errors remain unresolved. The initial batch size20 received HTTP413; reducing to10 exposed a provider requests-per-second limit. The resumable verifier now uses two calls per batch, one batch per1.05seconds, and stops on provider throttling. Contract URI responses containing `{id}` are classified separately as `template-matches-index` when the platform's decimal-number metadata path matches; they are not called exact resolved metadata-document reads.

Integration is intentionally additive: load records/evidence as another platform bundle, retaining `platformReleaseId`, `platformTrackId`, `releaseTitle` and `releaseTrackNumber`. Metadata is marked `indexed`; use recorded chain audit evidence separately. Do not show album-wide holders as song holders: collection ownership must be queried for the exact ERC-1155 token number. No collector histories or revenue totals were imported in this pass. The current loader and UI have not been edited by this agent.

Remaining completeness work: recover the seven missing public metadata references from explicit contract URI templates plus successfully read metadata, inspect contract deployment lineage/factory history for releases absent from the current public lists, and verify all public media independently. Supercollector's front page intentionally displays just40 latest/random releases; that front page is not the inventory source used here.

Final fixed-block audit: at Optimism block **159180072**, all 152 contract interfaces returned ERC-1155 support, all 623 public `uri(token)` calls returned successfully, and no provider reads remained unresolved. **581** URI templates match the indexed paths; **35** current contract templates differ from the indexed metadata directory, and **7** public tracks have no indexed per-track URI. The 35 differing-pointer records remain explicitly source-indexed, with the current read status/value/block attached as `contractURIRead`; they are not represented as current onchain metadata matches. The 7 missing references remain withheld.

The three exact approved LIL LIL/Pete tracks carry structured `pete-rango` Producer/Writer credits with original creditedName `Peter Arango`, tied to their exact release ID, contract, chain and track UUIDs. No general name-matching rule is applied. `scripts/build-supercollector.mjs` regenerates the bundle from the checked inventory and attaches the RPC audit without making network requests. Four focused tests pass for access gating, field sanitization, identities and exact approved credit mapping.
