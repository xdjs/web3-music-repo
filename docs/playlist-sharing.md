# Playlist sharing and recovered selections

Personal playlists and the recovered Sound playlist can be shared as a compressed URL fragment. The snapshot contains only a version, title and ordered catalog recording IDs. It excludes account identifiers, local playlist IDs, timestamps and other supplied fields. The fragment is not sent with the HTTP request; anyone receiving the link can nevertheless read its title and selection. This is a shared snapshot, not an access-controlled or continuously synchronized playlist.

Recipients can play available recordings and save an independent, editable copy in their local library. Unknown recordings stay visible as unavailable and are preserved when copying; they cannot trigger arbitrary media URLs. Sharing prefers the device share sheet, falls back to clipboard, then offers a selected link in the existing playlist dialog. Cancelling the native share sheet does not silently copy anything. Later edits do not update an already shared link. Large selections that exceed the URL budget are directed to the existing export action.

Limits: 100-character title, 5,000 recording IDs of up to 200 characters, 500 KB decompressed JSON, 24,000-character compressed payload. Decoding limits output while reading, rejects malformed/corrupt/unsupported payloads, and validates before rendering. All imported titles and IDs are escaped. The link contains catalog IDs, not remote media URLs; playback resolves only against the current catalog. Saving creates a new local UUID, and storage failures preserve the existing in-memory library. Account save/load remains the separate existing private library flow in My profile.

The historical Sound playlist actions play, save and share only the entries matched to this catalog, preserving their recovered order. The original archive list and its unresolved IDs remain visible with the existing provenance explanation. Song likes are available on recovered, shared and personal playlist rows.

Validation: `node --test tests/playlist-share.test.mjs` covers roundtrip/Unicode/ordered repeats, private-field omission, bounds/corrupt links/compressed bombs, native/clipboard/manual/cancel outcomes, and independent-copy/storage-error behavior. `scripts/verify-playlist-sharing.mjs` exercises the actual app in fresh browser contexts; its report records which original media started and screenshots cover existing light/dark desktop/mobile layouts. This does not verify account-authenticated synchronization or full-track playback availability for every recovered playlist entry.
